# Curated source workflow

This workflow connects a monitoring purpose to a bounded source selection, saved endpoint evidence and an importable collector configuration. Public MCP calls return saved metadata and perform no publisher requests. Operator registration changes and the separate bounded consumer are described below.

## Selections and provenance

The versioned [curation document](../curation/source-packs.json) contains three starter selections: `us-business` (six publishers), `japan-general` (five national-major selections followed by five digital, regional and explanatory supplements), and `korea-english` (three publishers, including specialized North Korea coverage). Every selected address is matched by country, endpoint type and canonical URL to registration IDs. Language, topics, aliases, section scope and official evidence are attached to those selected bindings only. Unregistered addresses remain explicit gaps rather than becoming invented registrations.

These selections are not complete national major-media lists, neutrality ratings or guarantees of usable articles. Each pack includes its known gaps and selection criteria. Official provenance establishes a declared address or scope; it does not establish universal current availability.

## Status and export policy

`get_source`, `get_endpoint_health` and pack endpoints retain the original structural audit fields and add `status_evidence`. The combined assessment uses the latest eligible actual collection or structural audit. The response preserves both observation times, their provenance, conflicts, content dates and nulls. Export generation time is never substituted for observation time. Invalid or future evidence is ignored; missing or corrupt required collection history is reported as unavailable evidence.

A valid empty feed, sitemap index and failed request have separate outcomes. Zero newly discovered URLs alone is not a failure. The first excluded baseline, an untracked null and a confirmed zero remain distinct. A content date older than 30 days is labeled by that explicit age rule; it does not estimate a publisher's normal cadence. Missing content dates cannot certify freshness.

A nonempty XML document with an explicitly recorded zero usable entry URLs does not establish article-list usability and is excluded. Compressed historical records do not retain total observed URL counts; their nonempty status is a saved XML outcome, with that evidence limit stated explicitly. URL totals are never borrowed from a different dated audit.

Default exports require an enabled registered binding, usable nonempty article-URL XML evidence at most 36 hours old and no stale or unreliable recorded content date. A missing content date remains explicitly unknown and may be included. The 36-hour cutoff accommodates a daily saved observation; it is a policy limit, not a live guarantee. Failed, unknown, stale, empty and index-only endpoints are excluded. Explicit `include=all` retains registered diagnostic entries and their exclusions, never converts them into working sources.

OPML contains RSS/Atom only and reports omitted sitemap counts. CSV/JSON preserve endpoint types and the separate collection, audit and content timestamps. CSV guards spreadsheet formula prefixes; XML escapes untrusted names and URLs. Exports are bounded and do not fetch publishers or article links. Importers that need sitemaps must use the typed exports rather than an RSS-only OPML file.

## Public interfaces

- MCP: `list_source_packs`, `get_source_pack`, `export_source_pack`; refresh an existing MCP connection's tool list after deployment.
- Search: `search_sources` accepts `pack_id` and curated aliases; `curation.matching_endpoint_ids` identifies which endpoints support curated language/topic matches.
- Homepage: `/` presents the selections in English by default, with Korean optional.
- HTTP: `GET /source-packs` and `GET /source-packs/{pack_id}/export?format=opml|csv|json`; add `include=all` only for diagnostic exports. These routes are read-only.

The submitted plugin skill source now documents the workflow. A deployed MCP change does not prove that a previously installed ChatGPT plugin has refreshed its tool cache or that directory skill metadata has been republished. Existing metric ingestion retains its bounded allowlist; new pack tool calls are acknowledged under `unknown` until a separate counter schema rollout. No user/query tracking is added.

Save the JSON content from `export_source_pack` (or the public JSON download) as `japan-sources.json`. From this repository's `packages/world-news-sources-mcp` directory, with its existing dependencies and compiled modules available, run:

```bash
node scripts/import-source-pack.mjs --input japan-sources.json --output japan-articles.json --selection-group national_major
```

The optional selection group limits requests to the major-publisher entries and requires typed JSON. Omitting it reads the entire selected list. OPML works for RSS-only imports. This standalone consumer follows same-origin sitemap-index children to bounded article metadata and extracts RSS, Atom, RDF and Google News title, URL and declared date fields. Both modern sitemap 0.9 and the exact legacy Google sitemap 0.84 namespace used by the observed Japanese news sitemaps are recognized. Unknown namespaces, DTDs and existing XML/transport protections remain rejected.

The default bounds are ten XML documents, one child level, 1,000 candidate items, two seconds between same-host requests and 90 seconds overall. Article bodies are never requested. Limits, missing dates, navigation URLs, HTTP failures, server waits and partial results are reported separately. A partial result is saved with a nonzero process exit status. Existing output files are not overwritten. Explicit `--include-excluded` is reserved for a deliberate consumer attempt using diagnostic exports; it does not change saved status or certify a failed address.

The consumer honors fetched robots rules. Per RFC 9309 section 2.3.1.3, a robots 4xx response other than 429 is recorded as unavailable policy evidence; actual resource 401/403 still blocks collection. Robots 429, network errors, server errors, explicit Disallow and oversized policy documents hold the request. This bounded consumer does not claim complete RFC conformance. Its decisions do not modify the production collector or source-addition approval policy. Source exports and MCP calls remain saved-data reads, while consumer results are independent files and never contribute to production NEW counts.


## Usable source defaults, October 26, 2026

Search, starter-pack detail, homepage lists and exports now share the default `include=usable` policy: an enabled selected address needs a saved positive extracted article-URL count within 36 hours and no stale or unreliable recorded content date. Missing content dates remain explicitly unknown. Failed, empty, index-only, unknown, stale and inactive bindings are accessible with explicit `include=all`, or stable-ID source/health diagnostics. Filtering occurs before pagination and applies to each selected typed endpoint; a failed sibling never hides the healthy address or leaks into the default list. Selection summaries distinguish matched, returned and excluded registrations/publishers and addresses without treating configuration totals as unique publishers. The homepage diagnostic checkbox updates both the visible list and its export links.

The existing aggregate history omitted extracted URL counts. Compact history version 3 appends only the already stored nullable integer `observed_urls`; versions 1 and 2 remain readable. Original collections, URL identities, tracking start, excluded initial baselines and source/country discovery counts are preserved. Referenced historical metadata is re-encoded from read-only existing collection details, without publisher requests, collection replay, registry synchronization or a database backup. Existing checks and collection times are retained. A missing old count stays missing, rather than becoming zero or a certified success.

Operator inventory capture, country diagnosis and investigation searches explicitly use `include=all` so failed sources remain observable and filtering cannot masquerade as deletion. Public diagnostic opt-in and direct source/health tools remain read-only. The optional query fields are exposed in the live MCP tool schema; this server deployment does not establish that cached tool schemas or directory skill text in existing ChatGPT installations have refreshed.
