# MCP usage and product outcomes

The application collector records **tools/call attempts**, including validation and tool errors. Initialize, tools/list, ping, notifications, `/health` and static pages are excluded. A successful tool returning an unhealthy publisher endpoint is a successful tool call.

Request counters retain UTC day, one of twelve existing fixed tool names plus `set_usage_analytics` (or `unknown`), a traffic hint, calls, successes, errors, duration sum/max and four latency buckets. No individual request log, request ID, IP, raw user or session ID, query, argument, prompt, conversation or result content is stored. Durations measure MCP handler completion, excluding the collector request; client network/model time is not measured. Values above 120 seconds are capped.

`daily_product_usage` adds bounded outcome counters grouped only by UTC day, traffic and channel (`mcp` or `web_export`). Search results are counted as nonempty, zero matches, empty page or unknown. A zero-match rate uses only known search results; empty pagination pages and unknown/error outcomes must be shown separately. Exports are nonempty, empty or unknown. Direct successful GET export downloads use the separate `web_export` channel and do not inflate MCP tool-call totals; HEAD requests and ordinary page visits do not contribute. An export is an intent signal, not proof that the user connected a working collector. No search term, selected country, pack ID or exported content is retained.

When `REPEAT_USAGE_ENABLED=1`, eligible successful unclassified MCP calls can add an optional client identity's presence to `usage_actor_days(day, actor_key)`. The MCP server derives `actor_key` from a supported OpenAI subject with HMAC under the existing metrics write secret. Raw subjects never leave that server. Presence retains no tool name or within-day event sequence and is deleted after 30 UTC days. Declared inspection, website, error, unknown-tool and preference-control calls do not add presence. Identity coverage counters distinguish provided, missing, excluded, suppressed and disabled measurements. Pseudonymization does not guarantee anonymity; keys can link retained activity days.

Daily distinct keys and keys also present on an earlier UTC day in the preceding seven days are estimates of client-supplied identities, not people or satisfied users. Same-day repeat calls do not constitute a return. Missing identity, secret rotation, client identity changes, bots and undeclared scans limit interpretation. Do not treat absent or disabled measurement as zero users. Label the activation date and incomplete seven-day lookbacks explicitly; earlier use is not reconstructed. This does not measure time saved or successful external collection.

## Repeat-use controls and activation

The `set_usage_analytics` MCP tool accepts only `{ "enabled": false }` or `{ "enabled": true }`. It uses only the current request's optional client metadata, never an identity supplied as a tool argument. Disabling deletes that identity's retained daily presence and stores `usage_opt_out(actor_key)` until re-enabled. Re-enabling removes the suppression key and does not reconstruct deleted presence. This persistent suppression key is the disclosed retention exception, not browsing history. Aggregate counters continue because they contain no per-identity linkage. If no supported identity or preference collector is available, the tool reports that a stored change was not applied or could not be confirmed; it must not return a fabricated success.

Clients may forward `Sec-GPC: 1`, `DNT: 1` or `X-World-News-Analytics: off` to suppress presence for that request. Header suppression does not persist an opt-out. Forwarding is client dependent. No website cookies or website actor tracking are introduced. A different identity or rotated secret may no longer match an earlier opt-out key.

`REPEAT_USAGE_ENABLED` is a collector-side gate and defaults to off. Deploy the matching privacy notice, additive schema and new tool first; allow the new tool's automatic OpenAI check to finish before enabling repeat-use measurement. Then explicitly set `REPEAT_USAGE_ENABLED=1` on the dedicated Worker. Until activation, aggregate outcomes remain available, identity coverage is marked disabled and no actor-day keys are written. Publishing the new tool does not backfill historical measurements. Source access and source-tool results do not depend on analytics availability or preference.

## Durability and limits

Dedicated Cloudflare Workers Free collector with a D1 Free binding. Parameterized SQL UPSERT increments counters atomically; no in-memory totals or read-modify-write race. Additive `CREATE TABLE IF NOT EXISTS` schema preserves the existing request-counter tables and rows. Apply `schema.sql` before the matching Worker is deployed; rerunning it must not clear retained data. Targeted SQLite tests verify concurrent increments, reopening, outcome separation, presence expiry and opt-out behavior. Remote D1 verification is required separately.

One authenticated aggregate write is attempted per identifiable tool call or applicable direct export. There is no blind retry or event-ID deduplication history. Collector timeout, quota exhaustion, network outage or terminated function can leave gaps. An ambiguous response can have committed even when the MCP returns `x-world-news-metrics: unavailable`. Totals are operational observations, not billing-grade exact-once records. Collector unavailability preserves source-tool results and emits a constant warning without user data. Successful acknowledgments are durable; the response header is `x-world-news-metrics: recorded`. Preference calls separately use the authenticated write-only `/v1/preference` route with a bounded `{actor_key, enabled}` body; the reply contains no identity key.

Free quotas are shared with other account usage. As documented September 30, 2026: Workers Free 100,000 requests/day; D1 Free 100,000 rows written/day, 5 million read/day and 5 GB total storage (500 MB/database). Index updates can increase rows-written usage. Free quota exhaustion rejects operations; do not switch to a paid plan. No paid add-on, log drain or dashboard authentication is created here. A daily Worker cron expires old pseudonymous presence; it does not collect publisher data.

## Owner access

Use the existing authenticated Cloudflare D1 Console and run `report.sql`; or use the approved local Wrangler OAuth login:

```sh
npx wrangler@4.145.0 d1 execute world-news-sources-metrics --remote --command "$(cat metrics/report.sql)" --config metrics/wrangler.jsonc --json
```

The collector exposes no public dashboard or arbitrary-query API. The private `GET /v1/daily-report?day=YYYY-MM-DD` route returns fixed daily aggregates only, authenticated by a separate `METRICS_REPORT_SECRET`. It accepts one exact closed UTC day within the previous 30 days, rejects extra query options, and never returns actor or suppression keys. This read credential cannot authorize aggregate or preference writes; the existing write credential cannot authorize report reads. Responses and errors use `Cache-Control: no-store`. A separate owner web dashboard would require its own access design.

`report.sql` combines all three request-counter tables and reports product outcomes and bounded daily return estimates separately. Owner reports must distinguish inspection from unclassified traffic, known from unknown outcomes, MCP from website exports and eligible identity coverage from total calls. Export aggregate reports without raw actor or suppression keys.

Pass the SELECT through `--command` to obtain its result rows. In the verified Wrangler 4.145.0 remote invocation, `--file` returned SQL-file execution metadata without SELECT rows; that receipt cannot establish a zero counter total. Owner OAuth was refreshed with the existing five effective scopes on October 14, 2026, and the read-only query returned 135 retained aggregate rows with zero rows written. An owner-read authentication error is separate from the MCP collector's write acknowledgment.

## Traffic separation

Operator smoke tests set `x-world-news-traffic: inspection`. Other calls use `unclassified`, not “real users.” This hint is client-supplied and spoofable. Always show total calls across both buckets and label inspection counts as declared; automatic OpenAI scans and ChatGPT demos cannot always be identified. Pre-activation tests are not retrospectively counted. The deployment evidence records the activation timestamp and controlled verification calls.

## Configuration

The MCP uses `METRICS_COLLECTOR_URL` (exact HTTPS `/v1/aggregate` endpoint) and `METRICS_WRITE_SECRET`. Only the dedicated collector's Worker secret and the Vercel project's production secret share the generated write value. Do not put it in source, reports, public plugin ZIP, CLI arguments or owner exports. No account-wide Cloudflare token goes to Vercel. Collector observability/log capture is disabled; infrastructure providers can still process network metadata under their policies.

Before enabling, publish a privacy notice matching aggregate fields, pseudonymous presence, opt-out controls, Cloudflare processing and retention. The public MCP remains unauthenticated; only collector writes require the secret. New outcome and identity statistics begin at activation and cannot be inferred from older aggregate-only rows. Existing source tool definitions stay unchanged; the preference tool adds a new definition that requires the platform's automatic check before ChatGPT can use it.

Sources: [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).

The three activity/inventory tool counters use `daily_activity_tool_usage`. Existing four-tool totals remain unchanged in `daily_tool_usage`. The two quality tools, three source-pack tools and preference tool use `daily_extended_tool_usage`; `report.sql` combines all three without rewriting historical rows. Public article-URL observations are stored separately in the operator SQLite ledger, never in usage counters.
